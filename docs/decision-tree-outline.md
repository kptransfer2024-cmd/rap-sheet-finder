# Decision tree — text outline

> Generated by `npm run docs:graph` from the live registries. Accessible equivalent of `decision-tree.mmd`.

## How routing works

1. Questions are asked **in the order below**. Each is skipped unless its condition holds. A condition may only refer to earlier questions, so the graph cannot loop.
2. Per-case questions (⟲) repeat for Santa Clara case 1 and 2 (or once for "three or more / not sure").
3. Any applicable question left unanswered (skipped, or "Show my plan now") is treated as its **"not sure"** option — never as "no".
4. Every rule whose condition holds adds an outcome card. The highest-priority card is shown as **Start here**; ties break by case number, then outcome id.
5. If no rule matches, `R-FALLBACK` shows `CANNOT_DETERMINE` (safe starting points + help).
